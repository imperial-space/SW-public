# Карта кода характеристик

## С чего начать

- [skills.yml](../../Resources/Prototypes/Imperial/Medieval/skills.yml) — основные коэффициенты, длительности и цены.
- [SkillScaling.cs](../../Content.Shared/Imperial/Medieval/Skills/Progression/SkillScaling.cs) — пороги 4/8/12/16/20, базовое значение 10, плавный множитель и стоимость уровней.
- [Описание реализации](skills-implementation.md) — игровые правила и результаты проверок.

Общего конструктора способностей, собственного планировщика или второго магазина нет. Используются системы событий, действий, статусов, бросков, длительных действий и гримуара, уже существующие в игре.

## Где искать правило

Пути в таблице относительны `Content.Shared/Imperial/Medieval/Skills/` и `Content.Server/Imperial/Medieval/Skills/` соответственно.

| Задача | Shared | Server |
|---|---|---|
| Изменение характеристик | `Systems/SharedSkillsSystem.cs`: `SetSkillLevel` | `Systems/SkillsSystem.cs`: `SetSkills`, выбор профессии и профиль |
| Прежние бонусы и плавный рост | `Systems/SharedSkillsSystem.<характеристика>.cs` | `Systems/SkillsSystem.<характеристика>.cs` |
| Сила: хват, пояс, захват, усиленный удар | `Progression/SkillStrengthSystem.cs`, крупный груз — `SkillHeavyCargoSystem.cs` | `Progression/SkillPerkSystem.Strength.cs`: отталкивание и снятие недоступной экипировки |
| Ловкость: прыжок и уклонение | `Progression/SkillJumpSystem.cs`, `SkillDodgeSystem.cs` | `Progression/SkillPickCraftSystem.cs`: отмычка; кража остаётся в `Steal/RandomStealSystems.cs` рядом с `Skills/` |
| Живучесть: действия в крите | `Progression/SkillActionSystem.cs` | `Progression/SkillVitalitySystem.cs`: еда, грязь, падения, передозировка; здоровье — `Systems/SkillsSystem.Vitality.cs` |
| Выносливость: контроль и стамина | `Progression/SkillEnduranceSystem.cs`, `SkillResourceSystem.cs` | `Progression/SkillPerkSystem.cs`: активка восстановления |
| Интеллект: работа, медицина и осмотр | `Progression/SkillActionSystem.cs`, `SkillWorkbenchSystem.cs` | `Progression/SkillPerkSystem.Examination.cs`; языки — `Systems/SkillsSystem.Intelligence.cs` |
| Интеллект: мана и заклинания | `Progression/SkillResourceSystem.cs` | `Progression/SkillMagicSystem.cs`: награды, цены, условия покупок; выдача заклинаний и UI остаются в `ImperialStoreSystem` |

## Как проходит изменение уровня

1. `SetSkills` сначала записывает весь новый профиль, затем отправляет `SkillLevelChangedEvent` для каждой характеристики. `SetSkillLevel` делает то же для одного уровня.
2. Серверный `SkillsSystem` обрабатывает здоровье, языки и старые таймеры. Возможности вроде усиленного удара проверяют актуальный уровень непосредственно при использовании.
3. После этого общее `SkillProfileChangedEvent` уведомляет модули ресурсов, действий, экипировки и магии. `SkillActionSystem` обновляет движение после `SkillResourceSystem`.

Не следует менять `SkillsComponent.Levels` напрямую: это обходит пересчёт ресурсов и отзыв возможностей.

## Состояние персонажа

| Компонент | Что хранит и зачем |
|---|---|
| `SkillsComponent` | Текущие уровни и прежние таймеры низкой ловкости. |
| `SkillProgressionComponent` | Исходные пороги ресурсов, выбранные языки и кулдауны пассивных бонусов. Сетевые поля нужны предсказанию прыжка, уклонения и контроля. |
| `SkillGrantedActionsComponent` | Серверные кнопки, их кулдауны и предыдущий уровень силы для отзыва экипировки. |
| `SkillMagicComponent` | Стартовая профессия мага и отметки уже полученных наград. Баланс, книги и покупки обслуживает обычный `GrimoireOwnerComponent`. |
| `SkillConstitutionStateComponent` | Таймеры рисков еды, грязи и падений. |
| `SkillDodgedProjectileComponent` | Кого уже пропустил конкретный снаряд; повторные эффекты того же попадания тоже отменяются. Для следующего броска отметки сбрасываются. |

При снижении уровня кулдауны и полученные награды сохраняются намеренно. Иначе изменение характеристик позволяло бы сбрасывать ожидание или повторно получать эссенцию. Каждый обработчик проверяет доступность бонуса по текущему уровню.

## Границы с общими механиками

`SkillsSystem` выдаёт учебный гримуар через `GrantStartingGrimoire` только при применении стартового профиля. Обычный пересчёт навыков книги не создаёт. `BindStoreOnEquipSystem.Learning.cs` разрешает единственную замену: учебный → свободный обычный. Переносится снимок покупок и баланса, обновляются ссылки возврата, старая книга превращается в пепел. Восстановление уничтоженной книги использует существующий `TryRestoreGrimoire`, не выдаёт награды повторно и не меняет тип книги.

Количество прыжков и доля цены используют общий `SkillScaling.JumpCharges`; стоимость меняется существующим `CheckDashStaminaCostModifiersEvent`. Для передозировки `MetabolismEffectAttemptEvent.Amount` содержит фактическое количество реагента в растворе, а не объём, переработанный за тик.

Удар/снаряд/контакт → `BeforeAttackEffectsEvent` на цели → `SkillDodgeSystem` → отмена до применения эффектов. Общие системы попаданий не вызывают уклонение напрямую. Для контакта со стационарным объектом уклонение не тратится.

Модификаторы скорости → `FinalizeMovementSpeedEvent` → `SkillEnduranceSystem`. Вторая фаза необходима, чтобы обработать все замедления после их накопления и сохранить штрафы брони и крита. Периодическое списание стамины выполняет сервер; состояния контроля сохраняют исходное оставшееся время.

Начало длительного действия → `BeforeDoAfterStartEvent` → `SkillActionSystem`. При проверке станка используется `SkillWorkbenchSystem.CanUse`. Переносимое действие должно явно разрешить помощь при движении через `AllowMovementAssistance`.

В движке допускается один обработчик пары «компонент + направленное событие». Если эту пару уже обрабатывает `SharedSkillsSystem`, дополнительное правило вызывается из существующего обработчика. Поэтому, например, темп атаки учитывает ловкость и штраф крита в одной подписке. Для уведомления нескольких модулей после смены профиля используется общее событие с `EntityUid`.

`AutoGenerateComponentPause` уже подписывает компонент на снятие паузы. Не нужно повторять эту подписку вручную для того же компонента. Отдельный словарь таймеров скрытой кражи сдвигается через обработчик `SkillsComponent` в системе кражи.

## Ограничения модульности

- `SkillPerkSystem` — одна система в трёх partial-файлах, а не три независимых модуля. Общая инициализация и выдача кнопок находятся в основном файле; осмотр и сила вынесены по файлам. Это небольшой серверный координатор, но для понимания его зависимостей нужно читать основной файл.
- Критическая скорость, доступ к станкам, прыжок и привязка гримуара всё ещё имеют явные вызовы между системами. Они централизуют правило, но не позволяют удалить модуль навыков без изменения вызывающего кода.
- Некоторые общие события хвата, слотов и потребностей объявлены внутри файлов навыков. Они являются простыми точками расширения, но их размещение пока привязывает общие системы к пространству имён навыков.
- Основной числовой баланс находится в YAML, однако списки разрешённого груза, материалов отмычки, базовых заклинаний и отдельных реагентов заданы в C#. Изменение такого списка требует правки кода. Для груза и бесплатных заклинаний явный список намеренно не распространяет бонус на новые наследники прототипов.
- Старые бонусы сохранены в `Systems/`, новые в `Progression/`. Таким образом, каждая характеристика не собрана в одном файле. Таблица выше показывает обе части.

Модули ограничивают размер отдельных обработчиков, но реализация не полностью изолирована от игровых систем. Дальнейшее разделение стоит делать по конкретной задаче поддержки, без отдельного фреймворка навыков или компонента на каждую цифру.
