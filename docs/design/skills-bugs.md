# Характеристики: реестр ошибок и внесённых исправлений

2026-09-24. Ниже сохранены исходные наблюдения до переработки. Первоначальный разбор выполнялся только по исходникам. Позднее пользователь отдельно разрешил сборку и тесты; их итоги приведены в [описании реализации](skills-implementation.md). Ручного игрового прогона не было.

Основание: статическое чтение текущего checkout. Игровые сценарии ниже ещё не проверялись на запущенном сервере. Отключённые механики отделены от ошибок применения: включать их автоматически не следует, поскольку готовится переработка характеристик.

## Замечания к балансу, не самостоятельные баги

- Ловкость 14 уже обнуляет дополнительный `DefaultSpread`; это не отменяет отдельную отдачу оружия.
- Сила 14 уже достигает нижнего предела времени самостоятельного освобождения из наручников.
- Выносливость 20 даёт ×0,3 к стамина-урону только там, где сопротивления не обходятся; спринт и рывок используют `ignoreResist: true`.
- Живучесть 20 блокирует тип урона `Poison`, а не все эффекты любых ядов.
- Текущие пороги разнесены по 1/5/6/9/10/12/14/15/16/17/20 и отличаются от границ иконок.
- Пересмотр характеристик должен одновременно обновить стоимость очков, требования профессий, интерфейс и гайдбук.

Связанный документ: [проект новой схемы](skills-rework-proposal.md). Последние решения пользователя реализованы; начальные коэффициенты остаются настраиваемыми.

## Реализованные решения

| ID | Изменение в исходниках |
|---|---|
| SK-01 | Рывок применяет отдельные модификаторы дальности и КД; прыжок использует тот же модификатор КД. |
| SK-02 | Модификатор крови применяется в естественной регенерации. Переливание не получает этот множитель. |
| SK-03 | Формула считает вероятность успеха: рост ловкости помогает, интеллект жертвы уменьшает её, результат ограничен 5–95%. Убрано накопление бонуса в компоненте. По дополнительному указанию пользователя второй случайный предмет сохранён на 20 при свободной руке, вместе с выбором основного предмета. |
| SK-04 | Рост живучести ускоряет восстановление сна. Снижение потребности сна у выносливости 20 применяется только к её накоплению. |
| SK-05 | DoorHack использует результат события расхода отмычки. |
| SK-06 | Стабильный выбор двух случайных языков на 16; на 20 все допустимые языки доводятся до полного знания. |
| SK-07 | Мана пересчитывается с учётом отдельно сохранённого множителя навыка, без повторного наполнения и накопления. |
| SK-08 | Правила зависят от текущего уровня; чужие компоненты расы/профессии не удаляются. Экипировка проверяется при снижении силы; одноразовые награды и КД сохраняются. Выученные языки/заклинания сохраняются намеренно. |
| SK-D01 | Отключённое снижение штрафа брони не включалось. Выносливость 20 конвертирует другие замедления, исключая броню и крит. |
| SK-D02 | Старые плоские +12 не включались. Пороги здоровья пересчитываются из исходных по единой плавной формуле. |
| SK-D03 | Общая формула времени медицинского действия подключена через событие; прежнее вычитание 0,25 секунды убрано. Мощность медицинского предмета и полученное лечение разделены. |
| SK-D04 | Событие подключено к UniversalLockpick; риск поломки уменьшается с ловкостью, настоящая отмычка на 20 не ломается. |

Дополнительно исправлены: изменение исходного словаря админской установкой уровня до пересчёта; обработка кражи стека из одной единицы; общий изменяемый словарь цен у копий ImperialListingData; потеря RaiseProductEventOnUser при клонировании; вычитание валюты `value1 - value1` вместо `value1 - value2`. Старые несовместимые профили получают безопасные характеристики 10 на выход с уведомлением, а не автоматическую санкцию.

Первые тесты и отдельные сценарии были удалены по указанию пользователя; после нового разрешения добавлены серверные регрессионные проверки. Отметка «внесено» здесь означает изменение исходников, а не подтверждённый результат игрового прогона. Результаты тестирования перечисляются отдельно.

## Ошибки, найденные запуском тестов

| ID | Найдено и изменено |
|---|---|
| SK-T01 | Сервер не запускался из-за нескольких обработчиков одной пары «компонент + событие». Уведомление о смене характеристик переведено в общее событие с идентификатором персонажа. Устранены повторные подписки на темп атак, спринт и начало длительного действия; для маны введено событие завершения начальной настройки. Логика отдельных модулей сохранена. |
| SK-T02 | Ручной сдвиг таймеров скрытой кражи при снятии паузы конфликтовал с автоматически созданным обработчиком `SkillProgressionComponent`. Ручная подписка перенесена на `SkillsComponent`; автоматическая обработка остальных таймеров сохранена. |
| SK-T03 | Удаление персонажа с купленным улучшаемым заклинанием вызывало добавление `PendingMedievalActionReplacementComponent` уже удаляемому владельцу. `MedievalActionReplacementSystem` пропускает удаляемый контейнер действий и исполнителя; обычное улучшение заклинаний продолжает обрабатываться. Ошибка обнаружена при завершении нового сценария перехода гримуара. |
